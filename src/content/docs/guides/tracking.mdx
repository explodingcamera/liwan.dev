---
title: Tracking Script
description: Add the browser tracker, send custom events, and configure properties and page exits.
---

Add the script shown for your entity in the liwan dashboard:

```html
<script
  type="module"
  src="https://liwan.example.com/script.js"
  data-entity="example"
></script>
```

The server-hosted script always matches the installed liwan version. If you use the `@liwan.dev/tracker` npm package, update it when you update the server.

## Custom Events and Properties

Use the npm tracker to send an event with properties:

```ts
import { event, setProperties } from "@liwan.dev/tracker";

setProperties({ plan: "pro" }); // Included on subsequent events and pageviews.
await event("signup", { properties: { method: "email" } });
setProperties({ plan: null }); // Remove the default after logout or a plan change.
```

Properties passed to `event()` override defaults. For the script-tag tracker, set defaults before loading the module so they apply to the first automatic pageview:

```html
<script>
  window.liwanProperties = { plan: "pro" };
</script>
<script type="module" src="https://liwan.example.com/script.js" data-entity="example"></script>
```

For computed properties or other changes to outgoing events, define a synchronous transformer before loading the script:

```html
<script>
  window.liwanTransformEvent = (payload) => ({
    ...payload,
    properties: {
      ...payload.properties,
      section: new URL(payload.url).pathname.split("/")[1] || "home",
    },
  });
</script>
```

The transformer receives the normalized payload for pageviews and custom events. Its `name` identifies the event, and its URL has already been sanitized. It returns the payload to send. It does not run for page-exit signals. Do not add personal data or sensitive URL parameters. Server-side globals are shared across requests, so pass request-specific properties directly to `event()` rather than setting global defaults.

Calling `trackPageviews()` more than once logs a message and ignores subsequent calls. Pageview tracking ignores navigations that only change the URL query or fragment.

Property values may be strings, numbers, or booleans. Null and empty strings are omitted. Each event can have at most 30 properties, with keys up to 64 characters and values up to 255 characters.

## Page Exits

liwan 1.7 enables page-exit tracking for pageviews by default. When the page becomes hidden, the browser sends a best-effort request that records the final page duration. This updates the matching pageview and does not create another pageview.

Disable the follow-up request in HTML:

```html
<script
  type="module"
  src="https://liwan.example.com/script.js"
  data-entity="example"
  data-exit="false"
></script>
```

Or disable it with the npm tracker:

```ts
import { trackPageviews } from "@liwan.dev/tracker";

trackPageviews({
  endpoint: "https://liwan.example.com/api/event",
  entity: "example",
  exit: false,
});
```

Exit tracking is ignored in server-side environments. The server also ignores exit updates when session metrics are disabled, visitor grouping is random per request, or no usable client IP is available.

Tracker requests send JSON using a CORS-safelisted `text/plain` content type to avoid a preflight request. Custom event clients can continue to send `application/json`.
